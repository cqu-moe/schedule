# 新外部课表订阅：当前学期、独立权益与自动同步

日期：2026-10-14（Asia/Shanghai）。本文定义待建设的功能与验收要求，不表示已经实现、部署或完成现场验收。

## Problem Statement

Schedule 当前保留外部课表订阅的数据模型，但搜索、创建和采集功能被禁用。用户无法将教师、教室、实验室、教学班或行政班的课表作为持续更新的日历使用。

学校课表接口不能沿用旧的纯 HTTP 获取方式。正常页面需要使用已登录学校账号选择目标，再触发受保护的业务请求；已有个人课表采集路径不能承担外部采集，否则可能把订阅主人的个人课表写入外部日历。

用户还需要分别控制个人与外部课表的自动同步频率和手动刷新次数。教学班只对应具体学期，换学期继续沿用旧教学班会产生失效或串课风险。

## Solution

提供一套只面向新建订阅的外部课表功能，覆盖教师、教室、实验室、课程中的具体教学班和行政班。用户搜索目标后创建订阅，服务在后台完成首次采集，并按管理员授予的独立外部权益自动更新或允许手动刷新。

首期只查询学校当前学期。教师、教室、实验室、行政班随学校当前学期更新；教学班订阅在学期更换时自动禁用，不自动选择同名课程或其他教学班。当前账号的学校页面没有跨学期查询权限，因此不提供固定或历史学期刷新选项。

Auth 负责学校会话、受限的页面动作与响应捕获；Schedule 负责订阅管理、目标校验、结构化课表及日历输出。旧外部订阅继续留在原有路径，本次不恢复、不迁移、不重新采集。

## User Stories

### 发现与创建

1. 作为拥有外部订阅权益的用户，我希望按教师搜索课表，以便关注其当前学期的授课安排。
2. 作为拥有外部订阅权益的用户，我希望按教室搜索课表，以便查看该教室当前学期已排定的课程。
3. 作为拥有外部订阅权益的用户，我希望按实验室搜索课表，以便关注对应场地的实验安排。
4. 作为拥有外部订阅权益的用户，我希望先查找课程再选择具体教学班，以便只订阅我需要的班次。
5. 作为拥有外部订阅权益的用户，我希望按行政班名称搜索，以便订阅该班当前学期的课表。
6. 作为搜索者，我希望候选显示足够的区分信息，以便避免误选同名教师、场地或班级。
7. 作为搜索者，我希望看到无结果和结果可能被截断的不同提示，以便知道是否需要缩小关键词范围。
8. 作为创建者，我希望明确看到学校当前学期，以便知道订阅覆盖的时间范围。
9. 作为创建者，我希望提交后立即看到首次同步状态，以便不必一直停留在页面等待浏览器采集。
10. 作为创建者，我希望首次采集失败后仍保留订阅并说明原因，以便按权限和提示重试。
11. 作为创建者，我希望首次成功之前不会把占位空日历显示为可用结果，以便避免误判功能已完成。
12. 作为持有旧外部订阅的用户，我希望能重新创建新订阅而不被旧记录阻挡，以便使用新的采集能力。

### 更新、日历与数据质量

13. 作为订阅主人，我希望后台按我拥有的外部自动同步间隔更新课表，以便无需保持页面或设备在线。
14. 作为订阅主人，我希望能在外部手动额度内主动刷新，以便及时确认学校的调课结果。
15. 作为订阅主人，我希望进行中的同一次刷新能被重复请求复用，以便避免重复采集和重复扣次。
16. 作为订阅主人，我希望看到上次成功时间、当前状态和外部手动剩余额度，以便判断日历的新鲜程度与可执行操作。
17. 作为日历使用者，我希望通过订阅链接读取持续更新的结果，以便在日历客户端查看安排。
18. 作为日历使用者，我希望只收到所选目标的课表行，以便不会混入其他班级或订阅主人的个人课表。
19. 作为教学班订阅主人，我希望普通课程和实验项目一起纳入，以便日历不会漏掉该教学班的实验。
20. 作为订阅主人，我希望名称、时间和目标归属都可验证的其他活动也能纳入，以便获得学校实际安排的完整信息。
21. 作为订阅主人，我希望无法导入的条目有明确提示，以便知道当前结果存在缺口。
22. 作为订阅主人，我希望合法空课表明确显示为该学期暂无安排，以便不把空结果误当服务故障。
23. 作为订阅主人，我希望刷新失败时保留上次成功结果并显示错误，以便不会因暂时故障丢失已有日历。
24. 作为日历使用者，我希望重复刷新不会重复生成同一安排，以便日历保持稳定且可追踪。

### 学期与生命周期

25. 作为教师、教室、实验室或行政班的订阅主人，我希望学校切换当前学期后自动查询新学期，以便持续关注同一目标。
26. 作为教学班订阅主人，我希望当前学期变化后自动禁用旧教学班订阅，以便避免旧班次错误延续到新学期。
27. 作为教学班订阅主人，我希望不会被自动切换到同名课程或任意教学班，以便课程身份保持可解释。
28. 作为订阅主人，我希望目标找不到、学校页面无权限和学校会话失效得到不同提示，以便采取正确的处理方式。
29. 作为订阅主人，我希望学校学期信息暂不可用时不会凭月份猜测学期或错误禁用订阅，以便保持状态可信。
30. 作为已删除或过期订阅的主人，我希望正在运行的旧任务不会把它重新启用，以便管理操作有最终效力。

### 权益与管理

31. 作为管理员，我希望单独配置用户的外部自动同步间隔，以便控制外部采集频率而不改变个人同步。
32. 作为管理员，我希望单独配置用户每天的外部手动刷新次数，以便控制外部使用额度而不改变个人刷新。
33. 作为管理员，我希望新权益全部由我主动授予，以便不会因上线自动复制旧权益或扩大权限。
34. 作为管理员，我希望未配置、明确零额度和明确无限额度不会被混淆，以便权限遵循实际配置。
35. 作为用户，我希望个人与外部手动次数独立计数，以便刷新一种课表不会消耗另一种额度。
36. 作为用户，我希望首次采集和自动同步不消耗手动次数，以便每日手动额度含义清楚。
37. 作为管理员，我希望撤销外部准入权益后停止新搜索和采集，并沿用现有订阅撤权规则，以便权限能够收回。
38. 作为管理员，我希望只移除自动更新权益时关闭对应动作，以便不会意外撤销用户已有的其他功能。
39. 作为使用共享链接的用户，我希望默认订阅链接与额外分享链接继续遵守现有不同的授权规则，以便分享能力变化不会混淆订阅权限。

### 稳定性与使用体验

40. 作为用户，我希望浏览器忙碌或短暂网络问题得到有上限的后台重试，以便服务能恢复而不要求我反复操作。
41. 作为用户，我希望需要重新登录或处理目标失效时得到明确行动提示，以便不会一直看到无意义的自动重试。
42. 作为平台维护者，我希望同一用户与同一订阅的并发请求受到控制，以便自动同步不会挤占全部浏览器容量。
43. 作为平台维护者，我希望搜索缓存按用户和目标上下文隔离，以便不同学校账号的可见范围不会混用。
44. 作为平台维护者，我希望旧消息与新消息选用各自的采集路径，以便旧外部任务绝不回退到个人采集。
45. 作为平台维护者，我希望日志与跨服务响应只包含必要业务信息，以便学校登录凭据和原始诊断不会泄露。
46. 作为键盘、手机或减少动态效果的用户，我希望搜索、创建、查看状态与重试都可正常操作，以便完整使用这项功能。
47. 作为验收者，我希望分别看到本地测试、服务集成、已登录业务流程和部署证据，以便准确判断哪些能力真正可用。

## Implementation Decisions

### 产品与授权合同

- 保留现有外部准入权益，新增外部自动同步间隔与外部每日手动刷新额度两项独立配置。不为现有用户补授，不从个人权益继承，也不为学生或助教预设初值。
- 未授予自动间隔时不执行周期采集；未授予手动额度时不允许手动刷新。外部准入、学校绑定、初次采集、自动采集和手动刷新分别检查对应条件。
- 自动间隔按分钟表达，使用现有十五分钟调度能力作为有效下限；不提供无限频率。手动次数允许明确的零、有限次数和无限，缺少配置不能变成无限。
- 外部手动次数按每用户每日所有新外部订阅合计，使用 Asia/Shanghai 自然日，与个人计数独立。初次与自动采集不扣手动次数。
- 接受一个新手动任务计一次；复用在途任务不重复计次。未成功入队不扣次；已经进入采集但最终失败仍属于一次已接受请求。冷却和服务限流仍然生效。
- 外部准入撤销继续影响订阅可用性，额外分享链接继续单独受共享权益控制。自动间隔或手动额度的撤销仅关闭对应采集方式。

### 新订阅与状态模型

- 以明确的来源版本区分新外部订阅和历史记录；来源版本贯穿创建、去重、队列、采集和结果写入。
- 旧记录不恢复、不迁移、不重新采集，也不能因旧目标相同阻挡新建。新功能配额和重复检查须显式排除旧外部记录；数据库约束与应用行为一致。
- 不批量删除旧数据或链接。保留原有旧记录查看、删除、冻结和权限对账路径，不添加迁移或重选入口。
- 创建保存订阅并异步排队首次同步。首次成功前呈现等待或错误，不把占位结果当成真实空课表。
- 同步结果至少区分等待、运行、完整成功、存在未导入内容和失败；学期过期与权益停用分别表达，避免权益恢复把过期教学班重新打开。
- 教学班绑定创建时的当前学期。可信学校当前学期变化后使其过期并停止新采集，不自动换班。过期公开链接的最终处理见 Further Notes。
- 其余四类随可信当前学期更新；目标失效时明确失败，不用同名候选替代。不得凭本机日期推断学校已经切换学期。

### 取数与服务边界

- Auth 新增限定业务参数的外部搜索与课表采集 RPC；搜索还需支持课程下教学班列表及当前学期上下文，不能只有课程目录。
- Auth 校验第一方服务身份、获批 RPC 方法、子系统、目标用户状态、外部权益与学校绑定，再通过现有学校会话管理和浏览器容量控制层执行。
- 浏览器只执行五类来源的固定动作：打开课表查询、核实当前学期、清理默认过滤、搜索并精确选择目标、捕获预期响应。课程同时覆盖普通课与实验项目。
- 业务合同不接受任意 URL、选择器、HTTP 方法或 POST 请求体。期望学期用于检查竞态，不能变成客户端任意查询历史学期的入口。
- 不修改学校页面权限或强行开启被禁用的学期控件。当前学期上下文不通过采集订阅主人的个人课表获取。
- Cookie、Bearer、浏览器存储、一次性防护密文和原始诊断留在 Auth；只返回经过基础校验与脱敏的业务数据和稳定错误分类。
- Schedule 独立校验数据、筛选目标、生成日历、维护订阅和同步状态。新 RPC 尚未部署或未授权时明确不可用，不回退旧 HTTP 或个人采集路径。

### 数据规则

- 响应状态、顶层结构和必需的捕获结果必须合法，之后才能判断目标和课表内容。空数组与获取失败分别处理。
- 教师按教师 ID 列表，教室和实验室按房间 ID，教学班按教学班 ID，行政班按嵌套教学对象中的行政班 ID 校验归属；不把其他目标的行透传到日历。
- 同一目标的普通课与实验合并时，以独立可验证的名称、实验项目、周次、星期、节次、地点和教师等信息区分安排，不能因课程同名误删实验。
- 只有名称、时间和归属可验证的其他活动才纳入。无法转换的活动明确计数并提示部分未导入；不能虚构信息，也不能把数据源本身不完整伪装成部分成功。
- 非成功响应、非法结构、缺少必需捕获、目标不匹配均保留旧成功结果并记录失败。合法空课表可以替换为明确的空结果。
- 保留现有日历事件标识规则，避免刷新造成重复事件。部分结果必须携带用户可见的完整性信息。

### 调度、缓存与一致性

- 外部任务有独立 provider；只有新版本外部订阅可进入该路径。旧任务安全结束，个人订阅继续使用原 provider。
- 现有定时入口按外部权益判断到期，分散任务，限制同一订阅的在途数量，并与同用户的学校浏览器容量协调。
- 搜索缓存按用户、来源、当前学期、关键词及过滤条件隔离，采用短期有效期；复用缓存前仍检查权限。
- 手动刷新不能被长课表缓存吞掉。优先复用同一在途任务或同批有效结果，失败不写入成功缓存。
- 结果写入同时验证运行标识、来源版本、生命周期及目标学期；删除、过期、撤权或更新的任务必须使旧结果失效。
- 容量忙碌、网络故障等可恢复错误有限退避；学校会话、权限、目标和学期错误分别分类，不能无限重试或错误地标记为需要重新登录。
- 未授予自动同步、旧记录冻结或临时服务故障都不能跳过现有权限对账。继续遵守已有公共缓存及撤权时效，不把服务端停用表述为立即删除客户端缓存。

## Testing Decisions

测试沿用前期设计中的公开行为边界，不新增只供测试调用的导出或开关。一个合同由最能观察结果的边界承担主要证明；其他层只测试其独有的传输、权限或时序风险。预期值来自独立样例和产品规则，不从被测实现重新计算。

| 测试边界 | 主要覆盖 | 不替代 |
| --- | --- | --- |
| Schedule API、定时/队列入口与公开日历读取 | 搜索与创建合同、权益与额度、异步状态、新旧隔离、目标结果、过期和迟到写入 | 学校页面真实可用性 |
| Auth RPC、学校会话控制层及固定浏览器采集入口 | 服务授权、绑定、动作限制、脱敏、忙碌/截止时间、响应捕获 | 不同学校角色的现场权限 |
| 用户界面公开交互 | 搜索选目标、首次等待、失败/部分导入、禁用操作、键盘和窄屏 | 后端安全与实际自动更新 |

复用现有路由/Worker 集成、外部任务防误入个人采集、同步运行标识写入、个人订阅生命周期、Auth RPC 授权、浏览器捕获以及前端交互的测试方式。纯适配器只承接需要固定脱敏样例验证的字段、目标筛选与日历转换，不重复重演整条路由。

必须证明以下可观察行为：

1. 未授权、学校解绑、旧 Auth 缺少新权益字段时不会误开放搜索或刷新；缺少额度与明确无限有不同结果。
2. 个人与外部计数互不影响；默认创建、自动同步、重复请求和队列失败按约定计次。
3. 旧外部记录和旧消息不能启动新采集，也不能阻挡同目标新建或造成新额度误计。
4. 五类来源分别只能输出所选目标；学生类型和任意业务动作扩展被拒绝。
5. 课程实验、多教学班响应、行政班嵌套归属以及同名候选得到正确处理。
6. 完整成功、部分导入、合法空课表与整体失败状态不同；失败不清空成功结果。
7. 当前学期查询不接受历史学期伪装；教学班过期后不会被重复消息、迟到响应或权益恢复重新启用。
8. 学期变化与采集中途删除、撤权、解绑的竞态不能造成错误写入。
9. Auth 不可用、未获批方法、浏览器忙碌、超时和学校会话失效有不同且不泄露秘密的响应。
10. 前端不会在尚无成功数据时宣称日历可用，部分导入有提示，禁用原因与可采取动作一致。
11. 五类各完成已登录的真实搜索、选择、创建、刷新和输出比对；固定样例和 mock 不能替代现场证据。
12. 最终分别记录本地验证、CI、Auth/Schedule 部署版本及真实日历结果；自动同步通过实际调度运行验证。

## Out of Scope

- 学生个人课表查询。
- 固定或历史学期实时查询，以及绕过学校跨学期权限。
- 旧外部订阅的恢复、迁移、目标重选和批量删除。
- 跨学期自动猜测教学班或把一个班扩展为整门课程所有班。
- 自动给现有用户补授新权益、从个人配置继承或填充学生/助教默认档位。
- 通用教务 URL/POST/UI 代理、跨账号采集结果共享和对外暴露学校凭据。
- 替换现有个人同步机制，或顺带重构整个权益系统。
- 本次规格发布不包含功能实现、PR 合并或部署。

## Further Notes

- **已验证能力边界**：2026-10-14 的登录页面显示当前学期为 2026 年秋，跨学期控件禁用；页面字段为 false，公开脚本以学校 `CrossSession&KR_TT` 权限控制它。存在十七项学期名称不等于拥有跨学期查询能力。该结论针对本次账号，不能推广为所有学校身份都不支持历史学期。
- **现场证据缺口**：原研究已验证课程与行政班的当期流程；教师、教室、实验室仍需逐类补齐网络与动作验收。课程实验的真实合并样例、非普通活动转换和容量上限也需在实施中验证，不能当作已验收。
- **一项保留的产品边界**：用户明确要求教学班换学期自动禁用，但尚未单独回答过期后原公开链接是停止读取，还是只保留历史快照。实现时必须使该选择明确；本规格不把助手提出的“整条停用并新建”记为用户已确认决定。停止后续采集和禁止自动换班已经确定。
- **相关既有问题**：[订阅额度中的默认个人管理行计数问题 #103](https://github.com/cqu-moe/schedule/issues/103)。新功能应与其对齐额度定义，尤其覆盖小额度用户；本规格发布不关闭或改写该问题。
- **跨仓部署依赖**：Auth 需要新的受限能力、错误合同及获批服务方法，Schedule 才能开启新入口。部署先后与回滚必须兼容，不能只打开前端开关。
- **证据与隐私**：研究记录只保留脱敏字段、动作和状态，不落学校会话、原始个人数据或防护密文。
