# 每周共享外部课表目录

Schedule 实现已通过完整后端 595 项、前端 232 项测试、类型检查、前端构建和设计规则检查。发布与首次同步状态以 [PR #151](https://github.com/cqu-moe/schedule/pull/151) 的发布记录为准；本文件说明采集与查询的固定契约，不把实现完成视为整轮名单已采集完成。

## 已确认范围

2026-10-15 用户同意从学校批量返回的教学班反查教师，只需覆盖本学期有课的教师，不要求未任课教师或全校人事名册。此决定替代此前“先找到完整教师名单才实施”的限制。使用用户已绑定的学校账号采集，全站有外部订阅权益且绑定有效的用户共享名称目录。实际课表仍通过订阅主人的学校会话获取。

名单每周更新。教室、实验室、行政班、课程、院系和教学班目录走固定批量入口；教师由教学班教师接口返回的稳定 instructorId 去重。教学班与课程的选择关系继续按请求用户、课程 ID 和学期按需缓存七天，过期后下次查询重新获取；不按同名课程或旧版 code 字段拼接，也不把其他用户的实时结果写入共享源账号目录。

## 采集与发布

- Auth 新增固定类型的 `cquExternalDirectory` RPC，沿用 `cquExternalSearch` 的客户端授权范围，并继续检查 calendar/external 权益、绑定与撤销状态。Schedule 不接触 Cookie、学校凭据或任意 URL 代理。
- 单轮同步先串行取得六类基础目录，再每批反查最多十个教学班。每个学校请求留间隔；每批完成后随机等待 60～120 秒再处理下一批。没有并发扫学校接口，也不把所有请求留在一次浏览器调用中。
- 当前 8,461 个教学班约需 847 个教师批次，加上目录、学期核验及重试请求。仅批间等待约 14～28 小时；浏览器启动、逐请求间隔与繁忙退避会继续增加耗时。这是预算，不是首次完成时间承诺。
- 源账号正在前台查学校或有近期排队/执行中的课表刷新时，目录批次延后。已经发出的短批次不能强制中断；Auth 原有会话互斥仍是最后保护。
- D1 保存本轮学期、阶段、待处理教学班、租约和下一次尝试时间。重复 Queue 投递受租约与下次执行时间保护；Cron 每十五分钟恢复遗漏投递，不在 Cron 内采集学校数据。
- 更新期间旧版可用。只有每个基础目录成功且每个教学班教师查询成功，才原子切换发布指针。教师数组为空可以表示该教学班暂无教师；业务失败、缺失班级、重复班级、错误结构不能当成空名单。
- 学期变化中止本轮，已知旧学期目录不再用于新选择。失败保留上一版数据；超过五天未完成的轮次终止，避免无限占用。仅保留必要名称、编号、院系和年级等目录字段。

## 查询行为

所有接口先检查请求用户的权益、来源开关和学校绑定，再读共享目录。命中后照常签发绑定当前用户的选择凭据。缓存不是新的学期观察，不会据此过期用户订阅。

前端先请求 `lookup=directory`；仅当返回 `409 EXTERNAL_DIRECTORY_MISS` 时自动改为学校查询，显示“目录中未找到，正在向学校查询，耗时会比平常稍长。”两个阶段共用原来的 100 秒预算及重试上限。其他错误直接沿用原有处理，不擅自回源。

## 学期证据与边界

现场 `AllCourseSchedule` 学期和 `/api/resourceapi/session/info-detail` 的 `curSessionId` 均为 `1061 / 2026秋`。批量教学班接口两个上限返回相同的 8,461 个唯一 ID。十门当前学期课程抽样的十六个班级全部包含其中。

本轮追加只读历史对照：课程 `10000000447` 在 `1059` 的班级 `720366`，及课程 `10000044234` 在 `1060` 的班级 `731228、731229、739209、739210`，均不在这份 8,461 条目录中。未切换学校账户的学期。这加强了当前学期范围的证据，但学校没有提供独立总数，不能宣称独立证明所有角色可见的全校全集。

采集器实现阶段使用其真实页面请求函数，均匀抽取六个教学班串行复测：`740923、739984、738973、745616、742978、744669` 均返回 HTTP 200 与业务成功，教师条数分别为 `1、1、1、4、2、0`，标识和名称类型均有效。最后一个验证了合法空教师列表。行政班的固定页面动作复测返回 4,700 个唯一 ID。这里验证的是登录浏览器中的请求函数，不能替代生产容器及整轮同步验收。

## 运维与验收

- 配置 `EXTERNAL_DIRECTORY_USER_ID` 为已明确同意共享的 Auth 用户 ID；不配置时同步及共享读取关闭。身份配置不写入 Git。
- 先发布 Auth 固定采集契约，再发布 Schedule 的 D1 迁移、调度与查询。Schedule 使用已有 Git Connector，不在推送后重复手工部署。
- 通过 D1 的 `external_directory_state`、`external_directory_runs`、各类行数与教学班 `collected` 计数核验：已排队不等于采集完成，已采集不等于已发布。
- 本地验证必须覆盖真实 D1 的失败保留、租约、重复投递、课程 ID/学期隔离、查询门禁和自动回源；Auth 另需容器解析、固定路径、节奏和会话撤销检查。生产仍需少量真实批次及前台业务验收。
- 回退先移除采集身份配置，停止新任务；保留 D1 表便于恢复。迁移只新增表，不改写已有订阅或课表。
