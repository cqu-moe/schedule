# 新外部课表订阅拆票草案

日期：2026-10-14。来源：[规格 #133](https://github.com/cqu-moe/schedule/issues/133) 与本轮用户补充。状态：用户调用 implement-spec 后进入实施；12 个子问题已发布，17 条原生阻塞边已读回验证。

## 本轮新增决定

教学班订阅过期后，订阅及其默认公共链接、额外分享链接一并停用。主人可以在原订阅中重新选择当前学期教学班；后台取得可用的新结果后，沿用相同链接重新启用。恢复受当前准入与分享权益约束。

这项明确决定补全并覆盖父规格 Further Notes 中的未决点。原先“过期必须新建、不给重选入口”的建议不再适用于新版本教学班；旧外部记录仍不恢复、不迁移。发布时把决定写入 T10/T11 子问题，不修改或关闭父规格。

## 拆分原则

- 以行政班建立第一条完整链路，随后按来源扩展；每票包含其行为所需的 Auth、Schedule、UI 和行为测试，不按技术层分票。
- 现有队列、运行标识、公开日历和界面可以复用。必要的局部预重构在使用它的票中先做；没有必须先独立完成的大规模机械重构。
- T01 的权益配置与 T02 的行政班搜索没有相互依赖，可同时开始。T04 手动与 T05 自动更新可并行，四类来源扩展彼此不互相阻塞。
- 除最终发布票外，各票交付能在本地或受控环境独立演示；公共开放仍须满足完整生命周期和每类真实验收，不能因部分任务完成提前开放不完整功能。
- 跨 Auth 与 Schedule 的同一行为保持一个纵向任务；可以关联多个仓库的 PR，不按仓库拆成人工等待链。
- #103 的默认管理行计数纳入 T03 验收，#109 的停用展示纳入 T10 的必要范围；两者不作为人为前置阻塞，也不在拆票时修改或关闭。

## 提议的任务与直接阻塞

1. **T01：[管理员独立配置外部同步权益](01-external-entitlements.md)**
   - **Blocked by：** 无，可立即开始
   - **交付：** 管理员可单独配置外部自动同步间隔和每日手动刷新次数，用户可看到两项有效权益；个人配置保持独立。

2. **T02：[搜索当前学期行政班](02-admin-class-search.md)**
   - **Blocked by：** 无，可立即开始
   - **交付：** 有权限且已绑定学校的用户能查看当前学期、筛选行政班，并区分无结果、截断、权限不足和登录失效。

3. **T03：[创建行政班订阅并异步生成日历](03-admin-class-first-sync.md)**
   - **Blocked by：** T02
   - **交付：** 选定行政班后立即得到首次同步状态，后台采集成功后可订阅真实日历；旧记录不阻挡新建。

4. **T04：[按独立额度手动刷新与重试](04-manual-refresh.md)**
   - **Blocked by：** T01、T03
   - **交付：** 用户可按外部专属每日额度刷新或重试失败的订阅，看到剩余次数、进行中状态及失败原因。

5. **T05：[按独立间隔自动更新外部课表](05-automatic-sync.md)**
   - **Blocked by：** T01、T03
   - **交付：** 用户离线时，已授予自动间隔的外部订阅仍定时更新，页面能显示同步结果；撤销该权益后停止周期采集。

6. **T06：[订阅教师课表](06-instructor-subscriptions.md)**
   - **Blocked by：** T03
   - **交付：** 用户能区分同名教师、创建所选教师订阅并取得可验证日历。

7. **T07：[订阅教室课表](07-room-subscriptions.md)**
   - **Blocked by：** T03
   - **交付：** 用户能选择准确的教室、创建订阅并看到该教室的当前学期排课。

8. **T08：[订阅实验室课表](08-laboratory-subscriptions.md)**
   - **Blocked by：** T03
   - **交付：** 用户能选择实验室并订阅其真实实验安排，实验信息不足时有明确提示。

9. **T09：[订阅具体教学班并合并课程实验](09-teaching-class-subscriptions.md)**
   - **Blocked by：** T03
   - **交付：** 用户先找到课程再选择具体教学班，日历同时包含该班普通课程和实验项目。

10. **T10：[换学期时更新目标并禁用过期教学班及链接](10-semester-rollover.md)**
   - **Blocked by：** T05、T09
   - **交付：** 四类长期目标跟随学校当前学期；教学班过期后停止采集，原默认和分享链接一起停用，主人能看见原因。

11. **T11：[保留原链接重选教学班并重新启用](11-reselect-teaching-class.md)**
   - **Blocked by：** T10
   - **交付：** 过期订阅的主人可重选当前学期教学班；新课表采集成功后恢复同一订阅及原链接，无需重新订阅日历。

12. **T12：[完成五类订阅的联调验收并逐类开放](12-release-and-business-acceptance.md)**
   - **Blocked by：** T04、T06、T07、T08、T11
   - **交付：** 在 Auth 与 Schedule 真实部署上验证五类新订阅、独立权益、实际自动更新及原链接重选，再开放通过验收的类型。

## 执行顺序与发布方式

初始可执行：T01、T02。之后只推进所有前置已完成的任务。任务编号是发布时的拓扑顺序，不表示必须串行执行。

每票已发布为 `ready-for-agent` issue，并挂为 #133 的原生 sub-issue；17 条直接阻塞关系使用原生 blocked-by，未降级为纯文本。父规格正文、标题及关闭状态已核验保持不变。

最终发布票只依赖 T04、T06、T07、T08、T11；其他所有任务已由这些依赖传递覆盖。T10 依赖 T05 提供的后台调度/容量控制以及 T09 的教学班身份；T11 依赖已具备一致过期状态的 T10。

本目录根下每个任务 Markdown 保留审核草稿；published 目录保存实际发布正文，已设置原生阻塞关系的正文不重复列 Blocked by。manifest 记录实际 issue 编号、依赖及父规格用户故事映射，不替代 GitHub 的任务状态。
