# 外部课表目录预同步：发现与决策

状态：研究记录。后续用户已接受按本学期教学班反查任课教师，实施进度与最新决定见[每周共享目录方案](2026-10-15-weekly-external-directory.md)。以下探针保留当时证据边界。

## 问题与目标

添加外部订阅时，学校浏览器查询可能返回 `EXTERNAL_BUSY`，前端等待后重试。用户希望提前获取教师、教室、实验室、课程、行政班名单，让常规搜索直接查已保存的目录。

目录只包含可订阅对象的标识、名称和检索信息；实际课表仍按现有订阅采集流程更新。课程目录与本学期教学班分别建模。

## 用户已确认

1. 目录每周自动更新一次。此决定替代本轮较早确认的每天更新。
2. 更新失败时保留上次成功的名单。
3. 本地目录没有匹配结果时，自动向学校查询，无需用户再点按钮。
4. 转为学校查询时，界面明确提示耗时会比平常稍长。候选文案：本地目录中未找到，正在向学校查询，耗时会比平常稍长。
5. 使用用户当前已绑定的学校账号统一同步名称目录，供已开通外部订阅的用户共用；实际课表仍由各自订阅主人的账号获取。
6. 基于逐课程请求的估算，用户先选择教学班按需缓存；随后明确要求继续寻找教学班按学期全量/批量入口。找到更便宜的批量能力后重新评估，不把逐门查询当成唯一方案。
7. 最初要求确认教师完整来源后再实施；后续明确接受从 8,461 个教学班反查教师，只覆盖本学期有课的教师，并要求分散采集请求。实施以这一最新决定为准。

## 当前学校页面观察

2026-10-15 在已有登录态下只读检查 `https://my.cqu.edu.cn/tt/AllCourseSchedule`：当前学期为 `1061 / 2026秋`。实际运行的 `AllCourseSchedule` 组件仍使用教师/教室/实验室 `limitNum=50`、课程 `pageSize=50` 和行政班 `pageSize=200` 的搜索请求。

页面暴露的查询参数包含 `limitNum` / `pageSize`，但这些参数本身不能证明服务端允许全量提取、真正分页或跨账号共享。旧报告中的前端 chunk 路径已变化，当前能力以此次现场核验为准。

### 批量查询现场结果

所有查询串行执行，仅保存标识、名称、编号、院系、年级和位置等目录字段；不保留教师接口原始对象内与搜索无关的个人字段。

| 类别 | 参数与观测 | 当前证据 |
| --- | --- | --- |
| 教师 | `filter` 的空关键词、通配查询和“张”均返回 10 条；调整 `limitNum`、`pageSize`、`limit` 未增加数量 | 不能全量；另一个公开前端所用 `matching` 端点返回 20 条且无总量元数据，也不能据此声称完整 |
| 教室 | 空名称，`limitNum=1000` 返回 1000 条，`5000` 与 `10000` 均返回相同 2532 个唯一 ID | 两个较大上限下集合一致，未提供独立总数 |
| 实验室 | 空名称，`limitNum=1000`、`2000`、`5000` 均返回相同 815 个唯一 ID | 三个上限下集合一致，未提供独立总数 |
| 行政班 | 查询 POST body 为 `[]`，`pageSize=1000` 返回 1000 条，`10000` 与 `20000` 均返回相同 4700 个唯一 ID | 两个较大上限下集合一致，未提供独立总数 |
| 课程 | 当前学期 `1061`，通配关键词，`pageSize=1000` 返回 1000 条，`10000` 返回 3800 个唯一 ID | 大查询一次 10 秒预算失败；后续有 45 秒预算的独立查询在 5644ms 返回 3800 条。不是稳定 SLA，尚需完整性回读 |

### 教师列表入口的权限核验

当前公开主脚本 `app.e20a2e81.js` 的路由映射指向：

- `FullTimeTeacher` → `chunk-d33a57c2.c5a45285.js`，页面方法读取 `GET /api/timetable/instructor/info/filter`。
- `TeachersManagement` → `chunk-2a5e960c.a6a32b5d.js`，页面方法读取 `GET /api/timetable/instructor-resource/page`。

使用现有学校会话及页面本身的 `getParamRequest`，以 `currentPage=1&pageSize=100` 只读验证：第一个接口业务返回 `status=error, code=error, msg=当前用户无操作权限`；第二个业务返回 `status=error, code=null, msg=操作失败`。因此第一个已确认权限受限，第二个失败原因仍不确定。不能将公开前端里存在列表代码当作当前账号能下载完整教师目录的证据。

已检查当前页面公开脚本中的普通教师查询入口：`instructor/filter` 与 `instructor/matching`；前者目前返回 10 条，后者 20 条。增大现有上限参数未产生全量目录，也没有得到可遍历分页或总数证据。尚未解决用户要求的教师完整名单前，不开始缓存功能实施。

追加检查普通 `instructor/filter` 的 `currentPage=2`、`pageNum=2`、`page=2`，均返回与第一页相同的 10 个 ID，未形成可用的分页方法。没有通过枚举关键词把零散候选包装成全量目录。

### 教学班批量入口核验

公开主包的 `TeachingClassManagement` 路由指向 `chunk-4272fd7c.8122c752.js`；真实 `tableData` 使用 `getParamRequest` 读取 `/class/list/filter`，响应结构读取 `data.data.content`、`totalElements` 和 `number`。模块常量核实 `p["E"] = /class`，不是根据名称猜测的 URL。

| 路径 | 只读验证 | 结果与边界 |
| --- | --- | --- |
| `GET /api/timetable/class/list/filter` | `sessionId=1061&currentPage=1&pageSize=20` | 业务返回“当前用户无操作权限”，没有获得列表或总数；有分页入口不代表当前账号能用 |
| `POST /api/timetable/class/list-by-multi-admin-class-id` | 公开主包确认 JSON 数组协议，使用已取得的一个 2026 级行政班 ID | HTTP 200，业务错误为“没有按行政班排课数据权限”，`data` 没有教学班数组；不能把 HTTP 200 算查询成功 |
| `GET /api/timetable/class/list-and-timetable` | 主包确认要求 `courseId` 与 `sessionId` | 仍是逐门课程，不是按学期全量入口；没有额外调用，避免无意义重复取数 |
| `GET /api/timetable/course/search-class-by-courseId` | 当前学期 10 门课程抽样 | 10/10 成功，是目前已验证的可用逐课程路径；未遍历全部 3800 门，因此不声称已取得完整教学班名单 |
| `GET /api/timetable/class/classNbr-filter` | 继续研究时从 `FreeTimeSchedule` 公开源码发现；空关键词，`limitNum=10000/20000` | 两次均返回相同的 8461 个唯一 ID，10 门课程的 16 个当前学期教学班 ID 全包含其中；没有独立总数，跨学期范围尚未验证 |

更新后的结论：教师完整目录与教学班管理分页遇到权限限制，但另一个普通教学班搜索接口已支持批量读取。教师完整目录仍未解决；新发现的教师安排接口只取得单学院 82 人。详见[教师替代路径研究](2026-10-15-teacher-directory-alternatives-research.md)。没有修改角色、绕过学校权限检查或改用其他用户会话。

常规精确教师查询在同一浏览器会话返回 1 条，用时 321ms；这只是本地已有浏览器会话内的学校 API 耗时，不等于生产 Auth 容器启动、排队和端到端查询耗时。

### 早期逐课程同步量估算与用户选择

从 3800 门课程目录均匀抽取 10 个位置，串行调用当前学期教学班查询：10/10 HTTP 200，共返回 16 个教学班；单次 111–318ms，均值 148.2ms。样本含 1 个合法空列表。样本教学班数不能外推为全校总数。

逐门方案需要约 3800 次学校请求。仅按此次本地已有浏览器会话内的平均 API 耗时外推，约 9.4 分钟；生产浏览器启动、网络、限速和重试未计入，后台预留 30–60 分钟只是设计预算，不是实测保证。用户随后改为每周更新。继续研究已找到可一次返回 8461 条的批量候选入口，因此 3800 次不再代表取得教学班目录所必需的最低请求数；需补充学期范围及课程 `codeR` 映射校验后再确定同步方案。

## 尚未解决的事实

- 每类目录的完整获取方式、返回上限、分页或分片条件，以及完整性判据。
- 普通账号可见名单是否一致；不同角色、院系默认过滤是否影响目录共享范围。
- 课程目录是否仅包含当前学期开课课程，以及教学班可否批量获取。
- 用户已指定当前账号作为目录采集身份，但这个账号尚不能访问已找到的教师完整列表；还需可用的全量来源。后续同步需要任务互斥，避免占用正在进行的用户查询。

## 待决定的产品范围

- 全站共享名称目录已获用户明确选择；必须记录授权采集身份和覆盖范围，不将“当前账号可见”写成“所有学校角色可见范围完全相同”。这是一项相对 2026-10-14 设计的明确范围变更。
- 教学班管理分页无权限，但普通教学班搜索已取得 8461 个稳定候选，可能显著降低提前同步成本。目前仍保留已确认的按需缓存决定；完成新路径的学期范围和 `codeR` 映射验证后再评估预填方案。目录更新与当前学期关联，不能沿用旧学期教学班。
- 换学期时目录切换与旧目录展示边界。不得用旧学期的教学班静默建立当前学期订阅。
