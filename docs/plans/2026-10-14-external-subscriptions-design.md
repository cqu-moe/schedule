# 新外部课表订阅设计

日期：2026-10-14（Asia/Shanghai）。状态：本设计已整理为[规格 #133](https://github.com/cqu-moe/schedule/issues/133)，并进入[拆票审核](./2026-10-14-external-subscriptions-tickets/README.md)。本轮明确的过期链接停用、原链接重选启用语义优先于父规格中的未决描述；尚未实现、测试或部署功能。

依据：[研究报告](../research/2026-10-14-cqu-all-course-schedule.md)、[学期权限补充核查](../research/2026-10-14-cqu-all-course-schedule-semester-access.md)、[访谈记录](./2026-10-14-external-subscriptions-discovery.md)、[领域术语](../../GLOSSARY.md)。研究报告的“首期不自动同步”和“恢复旧订阅”建议已被用户决定取代；其固定学期刷新目标未经验证，按补充核查修正。

## 用户已确定的范围

- 新增教师、教室、实验室、课程（具体教学班）、行政班五类外部订阅；不开放学生个人课表查询。
- 首期具备搜索、后台首次采集、定时自动更新和手动刷新。
- 只服务本次功能上线后新建的订阅；旧订阅不恢复、不迁移。
- 外部自动同步间隔、每日手动刷新次数为两项独立权益，全部由管理员手动配置；不自动补授，不从个人权益继承，不加入预设初值。
- 五类均基于当前学期。补充实测确认当前账号没有学校跨学期权限，首期不提供固定/历史学期选择，也不承诺跨学期刷新。
- 教学班在学期变化时自动禁用，公共链接一并停用，不跨学期猜测目标。主人可在原订阅重新选择当前学期教学班，取得可用新课表后沿用原链接启用。
- 首次采集异步进行，用户可离开页面；失败保留订阅、显示原因并允许重试。
- 纳入普通课程、实验项目与完整可验证的其他活动；部分内容无法导入时明确告知。

## 已确定的停用与重选语义

教学班过期后停止自动与手动采集，默认公共链接和额外分享链接均停用。主人可以在同一订阅中选择当前学期教学班，保留订阅身份及全部链接地址；新的首次采集取得可用结果后恢复，失败期间仍停用。重选后的恢复遵守当前外部准入和分享权益，不能恢复已失去分享权益的额外链接。旧生命周期的迟到结果不得写入重选后的目标。

该重选仅适用于新版本教学班，不是旧外部订阅的恢复或迁移。此前“固定学期订阅是否也停用”的问题已因上游权限核查撤回。

以下工程细节为本设计的明确建议，随整体设计一起确认。

## 权益与计费单位

保留现有外部订阅准入权益 `calendar.external`，新增：

| 权益 | 含义 | 未配置 | 明确配置 |
| --- | --- | --- | --- |
| `external_sync_interval` | 自动同步间隔，分钟 | 不自动同步 | 0 为关闭；正整数为间隔，调度有效下限 15 分钟 |
| `external_manual_refresh` | 用户每天全部新外部订阅合计可手动刷新次数 | 不允许手动刷新 | 0 为关闭；正整数为次数；明确无限为不限次 |

- 外部同步间隔没有“无限频率”选项。未知、缺失、非法值不开放能力；手动次数的明确无限必须与缺少授权行区分。
- 两项权益均由 Auth 管理界面配置。修改只作用于新外部订阅；个人同步间隔、手动次数和计数不变。
- `external=true` 且学校绑定 active 才能搜索、创建与采集。没有自动间隔仍可创建并做一次首次采集；手动刷新另看外部手动额度。
- 创建时首次采集、自动更新不扣手动次数。手动请求成功接受一个新任务计一次；重复点击复用进行中的任务，不重复扣次。采集发生后失败仍计已接受的请求，队列未接受不计次。
- 外部手动次数按 Asia/Shanghai 自然日计算，每用户独立于个人课表计数；沿用每条订阅的冷却与平台调用限流。
- 继续使用现有订阅数量和共享链接权益；旧外部记录不占新外部功能的配额、不阻挡同目标新建。
- 删除外部自动间隔或手动额度只关掉对应动作。撤销 `external` 才按现有规则停用整条订阅；share 只控制非默认链接。

## 订阅生命周期与界面

1. 新建页按五类目标提供搜索，显示学校当前学期，不提供学期切换。课程先选课程，再选具体教学班；行政班支持按名称搜索，并提示可能被上游截断的结果。
2. 创建立即返回订阅记录，显示“首次同步中”。首次成功前不把占位空日历呈现为已可用；首次失败显示原因和允许的下一步。
3. 首次成功后显示最后成功时间、自动同步状态及手动剩余额度，开放日历读取与复制。
4. 已有成功结果的订阅刷新失败，保留上次结果，并同时展示错误和旧结果时间；合法空课表显示“该学期暂无安排”。
5. 部分可验证条目已导入时显示“部分内容未导入”和计数，不能显示“全部同步成功”。目标归属、顶层 schema 或关键响应不可信时属于整体失败，不属于可忽略条目。
6. 教学班的学期失效是独立生命周期状态，不能复用会被权益对账自动重开的 `isActive` 单值。迟到任务、重复消息、权限恢复都不能抹掉该状态。
7. 对其他四类跟随当前学期的订阅，自动更新目标学期；目标不存在时显示明确错误，不猜测另一目标。
8. 教学班学期切换由可信学校学期信息判断，不用本机月份猜测。调度对账、用户读取和手动操作在取得可信新学期后执行一致的过期判断；学期元数据暂不可用时显示状态未能更新，不猜测过期。

## 新旧订阅隔离

- 新记录带外部 provider 版本标识；旧记录保留旧路径，不进入新外部搜索恢复、采集或重试流程。
- 不删除历史数据或链接，不执行旧目标重选/修复。旧订阅现有冻结和权限处理保持原样。
- 旧外部记录不参与新目标重复检查；数据库唯一约束也需分代，不能只改界面。
- 新功能的列表、创建候选及配额统计不被旧记录干扰。旧记录可保留在原来的查看/删除路径，不增加迁移入口。
- 消息消费者先验证来源版本，再选择 provider；旧外部消息安全结束，禁止回退为个人采集。

## Auth 与 Schedule 的边界

Auth 继续管理学校会话及浏览器操作；Schedule 管理订阅、结构化结果和日历输出。

- 新增类型化外部搜索与采集 RPC。参数仅为用户、来源类别、目标、期望的当前学期、搜索词及截止时间等业务字段，不接收任意 URL、selector、HTTP 方法或请求体。期望学期仅用于防止切换竞态，必须与教务当前学期一致，不是任意历史查询参数。
- 搜索合同明确区分目标搜索、课程下教学班列表、当前学期上下文；不能只返回课程 ID 而缺少教学班选择步骤。
- Auth 检查服务身份、获批方法列表、calendar 子系统、external 权益、active 学校绑定，再经现有会话控制层调用浏览器；更新 Schedule 服务身份获批的方法列表是部署事项。
- 独立固定页面动作处理五类来源，显式设置查询范围、核实页面当前学期并清理默认过滤，精确选择目标，等待对应业务响应；课程同时采集普通课程与实验项目。不强行启用被学校权限禁用的学期控件。
- 保留现有个人采集语义。外部元数据也走外部页面或允许的业务 GET，不为读取学期而采集个人课表。
- 返回脱敏业务字段、学期上下文及明确错误码；学校凭据、storageState、一次性密文和原始诊断不出 Auth。
- 新 RPC 尚未部署、未获批或合同不兼容时明确报告能力不可用；不能回退旧 HTTP 客户端或个人 harvest。

## 数据一致性与缓存

- 顶层课表结构、响应状态和必需 capture 严格校验；先验证目标归属，再转换为白名单业务字段。
- 课程按教学班 ID，行政班按嵌套教学对象中的行政班 ID，教师按教师 ID 列表，教室/实验室按房间 ID 过滤。出现多目标响应可筛出目标，不能把别人的行一起输出。
- 普通课与实验在目标确认后合并；去重同时考虑课程、目标、实验名称、周次、星期、节次、地点及教师，不能因同名误合并独立实验。用真实脱敏样本验证规则。
- 合法空数组可以成为成功结果；缺 capture、非 2xx、非法 schema、全部行目标不匹配不能当作空课表成功。
- 部分活动缺少可验证信息时记录未导入数量，不凭空补名称、日期或目标；若上游响应本身不完整，则整次失败。
- 搜索缓存建议 10 分钟，按用户、来源类别、学期、规范化关键词与过滤条件隔离。复用前仍检查权限，禁止跨用户共享绕过可见范围。
- 手动刷新不被长课表缓存吞掉。使用进行中任务复用及有限的同批结果复用减少重复采集，不拿失败覆盖成功缓存。
- 写入同时检查 runId、provider 版本、订阅生命周期和目标学期。删除、过期、撤权或新任务发生后，旧结果不得回写。

## 自动同步与失败处理

- 使用现有 15 分钟调度入口读取独立外部间隔；按实际授权判断到期，并分散入队，避免整点同时启动大量浏览器。
- 同一订阅只允许一个有效采集任务；同一用户的浏览器容量、限流与个人任务协调，忙碌不会被误认为学校登录失效。
- 每次采集设置统一截止时间。容量不足、网络暂时不可用等可重试故障使用有限退避；长期故障不在每轮 cron 中无休止重试。
- 学校会话失效、无页面权限、目标失效、学期过期分别处理，提供对应用户提示。需要用户处理的故障不高频重试。
- 权限对账与自动采集分离：未授予自动间隔、暂时禁用采集、旧记录被冻结，都不能跳过原有权限撤销处理。
- 保留现有公开链接缓存与权限撤销时效约定；不承诺客户端立即清除已缓存日历。新的学期过期状态与权限 inactive 一起参与公开读取判断。

## 实施顺序与验收边界

这项工作跨 Auth 与 Schedule，建议按能独立验证的完整业务路径推进：

1. **行政班完整链路**：独立外部权益、服务授权、新旧分代、搜索、后台创建、手动/自动采集、公开日历和错误状态。用已有研究证据先验证第一条完整路径。
2. **教学班完整链路**：课程到教学班选择、实验合并、当前学期与过期终态，验证新学期行为与迟到任务隔离。
3. **教师、教室、实验室**：分别完成真实搜索、选择、采集、目标过滤及日历比对，缺一类现场证据就保留该类未验收状态。
4. **可靠性与权限验收**：独立手动计数、缺失权益、撤权、解绑、同用户并发、队列重投、学期变化、合法空课表、部分导入与失败保留旧结果。
5. **上线验收**：先具备 Auth 能力与服务授权，再启用 Schedule 新入口。检查部署版本、真实创建、自动更新、公开 ICS/JSON 和日志；五类本地测试通过不等同五类已登录业务验收。

验收使用现有纯函数、Worker 路由/队列、Auth 会话控制层和前端交互测试边界，避免把内部实现细节锁进测试。重点证明：

- 未授权、未授予新额度、学校解绑时不会意外放行；旧 Auth 返回缺字段时安全关闭相应能力。
- 个人与外部额度互不消耗，旧外部记录不会入新队列，也不阻挡新建。
- 默认链接与共享链接分别按已有规则撤销；过期教学班不会被权益对账重新启用。
- 空课表、部分导入、整体失败有不同可见状态，失败不能清空历史成功数据。
- 新旧任务并发及学期变化后，旧响应不能覆盖新状态或写入错误学期。
- 搜索、取消、重试、键盘操作和窄屏状态保持现有设计系统行为。

Auth 实现在新的独立工作树进行；Schedule 使用当前独立工作树。任何发布前分别记录本地验证、CI、部署和已登录业务验收，不用其中一层替代另一层。

## 不在本次范围

学生个人课表查询、固定/历史学期实时刷新、旧订阅迁移/恢复、通用教务代理、共享学校凭据、跨账号结果缓存、自动给用户授予新权益，以及替换现有个人同步机制。
