# AllCourseSchedule 学期查询权限补充核查

日期：2026-10-14（Asia/Shanghai）。方式：当前已登录 Ego Browser，只读检查页面控件、页面权限布尔值与公开前端源码。

## 结论

**当前被核查账号只能通过正常页面查询当前学期，不能选择历史学期。跨学期是学校单独授权的能力，不能从 sessionId 参数或学期列表推导所有用户均可跨学期查询。**

本次没有测试具备跨学期权限的其他账号，也没有通过修改组件状态、权限或构造历史学期请求绕过禁用控件；因此不声称学校后端对所有身份都只支持当前学期。

## 直接证据

页面：[课表查询](https://my.cqu.edu.cn/tt/AllCourseSchedule)。

| 核查项 | 当前结果 |
| --- | --- |
| 顶部学期控件 | 显示 `2026秋`，包含 `ant-select-disabled` |
| 课表查询学期控件 | 显示 `2026年秋`，包含 `ant-select-disabled`，内部 input 也有 disabled 属性 |
| 正常点击查询学期 | 未展开可选择列表 |
| AllCourseSchedule 的 `hasCrossSessionFlag` | `false` |
| 页面学期选项数据 | 17 项，包括 2026 年秋、2026 年春等；存在选项不等于可以切换 |
| 当前页面权限集合中 Session 相关 KR_TT 权限 | 无 |

公开前端脚本：[chunk-70bbaea8.0b67f3e4.js](https://my.cqu.edu.cn/tt/static/js/chunk-70bbaea8.0b67f3e4.js)，本次读取 HTTP 200，与原报告引用的资源 URL 一致。相关代码明确：

```js
hasCrossSessionFlag: permissionCheck("CrossSession&KR_TT")
// 学期选择组件
disabled: !hasCrossSessionFlag
```

这里的 `permissionCheck` 是对构建产物中压缩函数名的可读转述；权限字符串、字段名和取反关系来自脚本原文。

顶部全局学期切换另由 `ChangeSession&KR_TT` 控制，见 [app.ef9f5d3f.js](https://my.cqu.edu.cn/tt/static/js/app.ef9f5d3f.js)。它与课表页的跨学期权限不是同一个字段。

## 对原报告和设计的修正

- 原报告已登录实测范围本来仅为当期学期。其“固定学期与当前学期都可刷新”属于未经验证的验收目标，不是已证明的上游能力。
- 新外部订阅首期按已确认的授权能力设计：只查询当前学期，不提供固定/历史学期刷新选项。保留学校返回的当前学期 ID 用于目标校验、缓存和生命周期判断，不开放客户端任意指定历史学期。
- 教师、教室、实验室、行政班继续跟随当前学期；教学班按用户已确认要求，在当前学期更换后自动禁用。
- 之前关于“固定学期教学班是否也禁用”的访谈问题失去首期前提，不再需要用户选择。
- 历史成功快照只是本地已有结果，不等于仍能从学校刷新历史学期。教学班停用后公开链接是否继续服务快照仍是独立的产品选择。
- 将来若支持具备学校跨学期权限的账号，需要另做该权限下的真实搜索、选择与课表验收，不能根据学期列表或 URL 参数直接启用。

原研究报告按原样保留，本补充核查优先用于解释其学期能力相关段落。
